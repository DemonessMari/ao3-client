Website tools use AO3’s interface and a separate saved website sign-in. The explicit website-session handoff can authenticate the native reader after a fresh server identity check. AO3 human-verification challenges require the user’s interaction. They are not native equivalents. The site controls availability and permissions; staff tools are not part of ordinary client parity.

Visual authoring supports paragraphs, bold, italic, underline, strike, headings, HTTPS links and flat bulleted/numbered lists. Unedited source is preserved. Unsupported HTML, such as tables, images, nested lists or custom styles, stays in HTML mode. Formatting is exported as semantic AO3 HTML. The app does not fetch work images while editing.

Native tools render AO3’s server-provided forms with native controls, including repeated fields, file uploads and supported nested sections. Permissions and tokens are checked again before submission. Uncertain writes are not retried automatically. Drafts and uploaded images remain in memory and are excluded from backups; passwords are cleared when leaving an editor. These tools require a connection. They do not reproduce every JavaScript-only interaction or staff tool.

Original formatting keeps external content off by default. Enabling it permits public HTTPS images, styles, fonts, audio and video without AO3 session cookies. Embedded players open separately with JavaScript enabled and no app bridge. Provider playback, regional restrictions and sign-in requirements depend on the host. Older saved copies need downloading again to gain preserved media markup. Simplified scrolling/book mode retains text, notes and basic inline formatting.

Verification still required: authenticated account writes and role-specific website workflows; phone rendering, accessibility, rotation/Back/file pickers and long reading sessions. Automated fixture tests and builds do not establish full website parity or device acceptance.

Read-aloud uses installed eSpeak NG on desktop and system voices advertised as offline on Android; it stops when leaving the reader or changing chapters. Android pauses when backgrounded and on audio-focus loss. Book-mode tap zones can assign previous/next/controls/no action to left, center and right, with adjustable zone widths. Android volume keys can be assigned previous page, next page or system volume separately. Profile-picture display and server-provided pseud image upload controls are native.

Chapter count is separate from the One Shot tag: the native chapter filter uses AO3's expected chapter count, while author-applied tags can be included/excluded through the tag fields. The app cannot infer whether a story is self-contained.

Auto-scroll is opt-in per reading session and stops at the chapter boundary. Speed is saved; starting automatically is not. Android volume navigation is opt-in: each key can advance, go back or control system volume, with ordinary volume controls retained outside the reader and while reading dialogs are open. Keep-screen-on applies only while the reader is displayed.

Series navigation fetches AO3 work metadata on request and uses its supplied previous/next visible-work links for each membership. It opens the chosen work in native details before reading. Full series listings and subscriptions are native. Series lists require a connection. Native skin layout tokens are documented in SKINS.md.

AO3 Reading History and Marked for Later are fetched on request after verifying the current account in the response. They remain separate from local recent reads. Activity text is displayed in memory and excluded from local library metadata/backups. Viewing these lists does not submit deletion or clear-history forms. The history view offers individual deletion and clearing after confirmation; both fetch a fresh, account-verified form and submit once. AO3 history deletion also removes the corresponding Marked for Later flags. The AO3 history preference is available in native account preferences.

Native AO3 lists can filter entries on the current page. Inbox selections use AO3’s repeated record fields in one bulk request. Native AO3 lists verify the response account before displaying private data or submitting an action. They are fetched on request and not included in library backups. Unsubscribe and inbox actions fetch fresh forms/tokens and submit once; uncertain results require a refresh. Comment actions only appear when supplied by AO3 for the current user, and recheck permissions before submission. Fixture tests do not establish production account permissions or successful live writes.

Account editors fetch AO3’s current form and available options. Saving rechecks the account and form, preserves untouched fields changed elsewhere, and rejects conflicting edits. Unsubmitted drafts remain in memory until discarded or sign-out. Pseud image uploads, icon descriptions and removal are native. Muting uses AO3’s numeric user visibility rules for online lists/comments and does not remove saved offline copies or prevent explicitly opening a work.
